# Project 4 - Customer Insights, Segmentation, Recommendation (ML solution + Streamlit Dashboard Report)

## Project Overview

This project demonstrates an end-to-end customer analytics and ML workflow built from transaction data, including:

- data ingestion and adaptive cleaning,
- customer-level feature engineering,
- customer segmentation (clustering),
- segment-based product recommendation,
- extended marketing insight scoring (churn risk, CLV estimate, transactional promoter proxy),
- low-latency read-only API serving,
- and a Streamlit dashboard for analytics + personalization lookup + quality monitoring.

The system follows an offline-first architecture:
- heavy computation is done in offline refresh jobs,
- online services only read precomputed artifacts for fast inference retrieval.

## Pipeline Execution Flow

### Offline Refresh (Batch)

Run:

```bash
python -m app.jobs.refresh_insights
```

This triggers the full flow:

1. Load transaction CSV
2. Build dataset profile (null/duplicates/cancellation/skew signals)
3. Adaptive cleaning
4. Customer feature engineering (RFM + behavioral features)
5. Clustering (KMeans/GMM, optional PCA, silhouette-based K selection)
6. Extended insight scoring
7. Segment-based recommendation generation
8. Save artifacts (`parquet`, `joblib`, `meta`)
9. Run quality monitoring evaluation and store reports

---

## Serving Layer (Read-only API)

Run:

```bash
python -m uvicorn app.api.main:app --host 0.0.0.0 --port 8000
```

Endpoints:
- `GET /health`
- `GET /v1/customers/{customer_id}`
- `POST /v1/customers/insights`

The API loads `customer_insights.parquet` into memory (`InsightStore`) at startup and serves low-latency lookups.

## Streamlit Dashboard

Run:

```bash
streamlit run app/streamlit/dashboard.py
```

Dashboard sections:
1. Data Analysis: KPI cards, trends, top countries/products, hourly revenue, segmentation visuals
2. Customer Personalization: customer-level history, feature table, API inference JSON
3. Quality Monitoring: latest evaluation status, per-category checks, trend history across runs

Generated by offline pipeline:

- `app/artifacts/customer_insights.parquet`  
  Customer-level precomputed insights for API/dashboard.
- `app/artifacts/clustering_bundle.joblib`  
  Clustering model bundle (model/scaler/PCA/transform metadata).
- `app/artifacts/pipeline_meta.json`  
  Pipeline metadata (profile, cleaning report, feature info, clustering metrics, timestamps).
- `app/artifacts/evaluation/evaluation_report.json`  
  Latest quality evaluation report.
- `app/artifacts/evaluation/history/run_<UTC>.json`  
  Historical evaluation snapshots.

---

## Quality Monitoring (Soft Report Mode)

Each refresh run evaluates:

- Data quality (schema, row count drift, null/duplicate/cancel ratios)
- Feature quality (null/inf checks, bounds, PSI drift)
- Model quality (silhouette, davies-bouldin, cluster balance, K stability)
- Business metrics (coverage + score distribution drift)
- Regression vs previous run (intersection-based stability checks)

By design, this is soft-report monitoring:
- pipeline still completes,
- artifacts are still produced,
- status is used for observability and trend tracking.

All settings are controlled via environment variables with prefix `RETAIL_`.

Examples:
- `RETAIL_CLUSTER_ALGORITHM`
- `RETAIL_K_MIN`, `RETAIL_K_MAX`
- `RETAIL_PCA_VARIANCE_RATIO`
- `RETAIL_TOP_PRODUCTS_PER_SEGMENT`
- `RETAIL_RECOMMENDATIONS_PER_CUSTOMER`
- `RETAIL_EVAL_ENABLED`
- `RETAIL_EVAL_MIN_SILHOUETTE`
- `RETAIL_EVAL_PSI_WARN`
- `RETAIL_EVAL_HISTORY_KEEP_RUNS`
